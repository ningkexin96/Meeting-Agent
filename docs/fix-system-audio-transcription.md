# 实时转录抓不到「线上会议对方」的声音

## 现象

开始实时会议后，自己说话能实时出字，线上会议（腾讯会议 / 飞书 / 钉钉 / Zoom / 浏览器里的 Meet 等）
里对方说的话**一条都识别不到**。

## 根因

原来整条链路只有**一个音源：本机麦克风**。

```
修改前：
  麦克风 ──► AudioContext(16k) ──► AudioWorklet ──► PCM ──► WS ──► DashScope ──► speaker_0

  会议对方的声音 ──► 扬声器/耳机播放 ──► ✗ 从未进入音频链路
```

涉及的三处代码（都在改造前）：

| 位置 | 问题 |
| --- | --- |
| `components/live/use-realtime-asr.ts` | `getUserMedia({audio: true})`，只有麦克风 |
| `components/live/use-live-recorder.ts` | 分片模式同样只有麦克风 |
| `lib/asr/ws-realtime.mjs` | 所有识别结果硬编码 `speakerLabel: "speaker_0"` |

这不是识别服务的问题（DashScope 工作正常），而是**对方的音频压根没被采集**。
浏览器的安全模型不会让网页直接录「系统正在播放的声音」，必须由用户显式授权一次。

## 修复方案

改成**双音源**，两条独立轨道分别送识别、分别打说话人标签：

```
修改后：
  麦克风       ──► AudioContext(16k)  ──► Worklet ──► [头0]+PCM ──┐
                                                                   ├─► WS ─► DashScope ×2 ─► speaker_0 / speaker_1
  系统播放音   ──► AudioContext(48k)  ──► Worklet(重采样) ─► [头1]+PCM ┘
  （getDisplayMedia 共享「整个屏幕 + 系统音频」得到）
```

要点：

1. **1 字节轨道头**：每帧 PCM 前加 `0`（麦克风）/ `1`（系统音），同一条 WebSocket 承载两路，服务端按头分发，互不串话。
2. **两路各开一条 DashScope 会话**：混成一路会丢失说话人信息，之后没法区分谁在说。某一路启动失败只影响那一路。
3. **系统音必须重采样**：`getDisplayMedia` 在多数机器上只给 48kHz/立体声。
   直接用会把语速拉快 3 倍，所以 `public/pcm-processor.js` 里做了线性插值降到 16kHz 并混单声道。
4. **不要开回声消除**：麦克风那侧开 `echoCancellation`（防止外放时把对方声音也收进来，避免一句话认两遍），
   系统音那侧单独用 48kHz 上下文，不参与回声消除，否则 Chrome 可能把对方人声当回声削掉。
5. **落库归属**：`live_segments.speaker_label` 写 `speaker_0` / `speaker_1`；
   结束会议时 `endSession` 会分别为「实时转写（我）」和「会议对方」建 `MeetingParticipant`，
   后续可以在说话人页把「会议对方」改成真实姓名。分片模式同样按 `source` 字段打标，且**跨片拼接只在同音源内进行**。

## 怎么用

1. 开始实时会议（只需麦克风权限）。
2. 点面板上的 **「采集对方声音」**。
3. Chrome/Edge 弹窗里选择 **整个屏幕**，并勾选底部的 **「同时共享系统音频」**（英文版：*Share system audio*）。
   - 只想录某个会议标签页时，可改选「标签页」并在该标签页里勾选「同时共享标签页音频」。
4. 面板会显示「我已转写 / 对方已转写」两个计数，转写列表里每条都带 **我 / 对方** 标签。

> 注意：只共享画面、不勾系统音频时，面板会明确提示「对方声音已开启，但 3 秒内没有收到任何音频」，
> 不会静默失败。

## 平台限制与备选方案

| 场景 | 能否拿到对方声音 | 说明 |
| --- | --- | --- |
| Windows + Chrome/Edge，选整个屏幕并勾选系统音频 | ✅ | 本次实现的主路径 |
| Windows + Chrome，选单个窗口 | ❌ | 窗口共享不带音频，必须选「整个屏幕」或「标签页」 |
| macOS + Chrome，共享整个屏幕 | ✅ | 需要 Chrome 有「屏幕录制」权限（系统设置 → 隐私与安全性） |
| macOS + Chrome，共享标签页 | ✅ | 只要该标签页本身在放声音 |
| 任意系统，Safari / 旧版浏览器 | ❌ | 不支持系统音频采集，需改用 Chrome/Edge |
| 会议声音走 USB 会议麦（如全向麦）自带扬声器，声音不经过系统混音 | ⚠️ | 见方案 B |

### 方案 B：虚拟声卡回环（系统声音完全不经过混音时）

装了 VB-Cable（Windows）/ BlackHole（macOS）后，把会议软件的**播放设备**选成虚拟声卡，
浏览器麦克风里就会出现 `CABLE Output`。这样对方声音会以「麦克风」身份进来——代价是设备标签是
`speaker_0`，需要用户手动在设置里选对设备。

### 方案 C：直接接入会议平台的官方转写 API

如果对方是腾讯会议/飞书/钉钉企业版，平台侧自带的录制转写更完整（能拿真实的参会人身份）。
缺点是需要企业管理员开权限、按会议拉取，不是「本机实时」能力。
