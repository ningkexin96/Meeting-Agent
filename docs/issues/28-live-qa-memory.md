## 背景

`#27` 把会中提问做通了，但回答**只看本场会议到现在为止的转写**。

真实会议里，很多问题天然是跨会的：

> 「之前关于排期是怎么定的？」
> 「上次说灰度怎么做来着？」
> 「这个风险以前提过吗？」

这些内容本场还没人说过，只在本场转写里找，只能回答「没找到」——但系统里其实有。

## 关键约束：不能把历史结论说成本场结论

这是本需求最主要的风险，也是最主要的实现成本。

会中问答的答案会被当场读出来打断发言，一旦归属错了（把上周的决议说成今天定的），
危害比「答不出」大得多。所以记忆不能简单拼进上下文，必须：

1. **在上下文里单独成段**，明确写「不是本场会议的发言」
2. **在提示词里写死规则**：引用必须带「之前 / 上次」并说明来源会议；与本场冲突时以本场为准
3. **在界面上单独展示**，用不同颜色和本场出处区分开

## 目标

1. 会中提问能召回本租户的往期记忆（决议 / 未闭环 / 事实 / 经验）
2. 记忆召回**只接受真正命中的条目**，不做「最近几条」式的兜底
3. 已过时 / 有冲突 / 已遗忘的记忆**一律不参与**
4. 与会中转写共用同一套检索口径（同一份词表、同一套「不硬凑」规则）

## 关键设计决策

### 1. 为什么记忆不参与跨会向量检索

项目里已有 `hybridRecall`（`lib/rag/retriever.ts`），但直接复用有两个问题：

- **它依赖 embedding 服务**。未配置 `EMBEDDING_BASE_URL` 时用的是 bigram 哈希向量，
  该文件自己的注释就写明了：哈希向量无法区分相关与无关（实测无关问句 0.178，正确命中 0.200）。
  拿它做记忆召回，等于把幻觉风险从"模型"转移到了"检索"。
- **它的关键词权重表（`lib/tools/keywords.ts`）与本链路不一致**。两套口径会让用户换着问
  「谁负责」和「之前谁负责」时得到不一致的判断。

因此这里复用了 `#27` 已有的打分器（`scoreText`），只额外收紧一道闸门（见下条）。

### 2. 为什么记忆比转写更严格

本场转写允许「意图词」单独命中（问「有什么风险」，原文说「有个风险」就是答案）。
记忆**不允许**：记忆是长期知识，「上线」「负责」这类词几乎每条决议都有。

实测：「量子计算什么时候上线」会因为擦到「上线」而召回「上线排期定在月底」。
所以记忆检索额外要求命中**实体词**；同时把「上线 / 功能 / 需求 / 方案 / 版本 / 项目 / 开发 / 设计」
从实体词降为通用词。

### 3. 为什么「刚才说了什么」不召回记忆

这类问句没有实体词，在本场转写里会退化成「最近的片段」。如果记忆也这样兜底，
用户问「刚才」时反而会看到上个月的决议。所以记忆检索在无实体词时直接返回空。

### 4. 记忆池的容量上限

按重要性取前 `LIVE_QA_MEMORY_POOL`（默认 800）条。会中提问是同步请求，
不能让记忆体量增长线性拖慢每次提问；同时 800 条对中小团队足够覆盖。

## 验收标准

- [x] 会中提问能答出只在往期记忆里出现的内容
- [x] 回答明确说明这是「之前 / 上次」的结论，不说成本场结论
- [x] 已过时（superseded）的记忆不会被当作依据
- [x] 与本场无关的记忆不会被召回
- [x] 问「刚才说了什么」时不出现往期内容
- [x] 接口回传引用的记忆（来源会议 + 相对时间），界面单独分区展示
- [x] 模型不可用时，兜底回答也把本场内容与往期记忆分开列
- [x] 跨租户记忆不可见

## 不做

- 多轮对话式追问（仍为单轮）
- 记忆的自动去重与合并（沿用记忆管理页的人工状态流转）
- 往期会议**转写原话**的召回（只召回已沉淀的结论，避免把历史原话当成今天的发言）
