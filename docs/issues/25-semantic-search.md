## 背景

原实现是字符 bigram 关键词匹配（`lib/tools/keywords.ts`），只能命中「字面相同」的内容。
用户问「上线时间是什么时候」，历史纪要里写的是「月底发布第一个版本」——关键词完全对不上。

上一轮 `#25` 记的是 backlog，本轮落地。

## 目标

- 向量索引：话轮 / 摘要 / 决议 / 记忆统一入 `Embedding` 表
- 混合召回：关键词（精确、可解释）+ 向量（语义、模糊），用 RRF 融合
- 关键：**不能因为「总能返回最近的」就把无关内容当依据**

## 关键设计决策

**为什么用 RRF 而不是加权求和？**
关键词分和向量分量纲不同（0~1 的比例 vs 余弦），加权求和需要反复调权重且不稳定。
RRF 只看排名，`score = Σ 1/(k+rank)`，对两路分数的绝对值不敏感，业界验证过更稳。

**为什么不能用固定相似度阈值过滤向量结果？**
这是本 issue 最重要的发现。实测数据（bigram 哈希向量，64 维）：

| 查询 | 最高分 | 是否相关 |
|---|---|---|
| 存储怎么处理 | 0.200 | ✅ 相关 |
| 今天天气怎么样 | 0.178 | ❌ 无关 |
| 量子计算什么时候上线 | 0.167 | ❌ 无关 |
| 上线时间是什么时候 | 0.154 | ✅ 相关 |

**相关项和无关项的分数完全重叠**，任何单一阈值都会错杀或放过。
最终策略：
- 关键词有命中 → 向量作补充，用**相对阈值**（与最高分差距 ≤ margin）放宽召回
- 关键词完全没命中 → 只接受**强向量命中**（≥ 0.25），否则宁可不召回

代价是牺牲了一部分纯语义召回（「上线时间」这类问法可能召不回），
但换来的是「不把无关内容当依据」。在会议纪要场景，**可信度优先于召回率**。

## 验收标准

- [x] 中文切 bigram、英文按词、数字保留
- [x] 同文本向量一致且已归一化
- [x] 关键词链路能与向量链路共同召回
- [x] 命中结果标注来源（keyword / vector / 双路）
- [x] 双路命中获得 RRF 加权
- [x] 结果按分数降序
- [x] 跨租户查不到（隔离）
- [x] 重复建索引不产生重复行（幂等）
- [x] 完全无关问题不召回（防幻觉）
- [x] 空查询不报错

## 实现

| 文件 | 作用 |
|---|---|
| `lib/rag/embedding.ts` | HTTP embedding 服务 + bigram 哈希离线兜底 + 中文分词 |
| `lib/rag/retriever.ts` | 建索引、关键词召回、向量召回、RRF 融合、`indexMeeting` |
| `lib/tools/index.ts` | `recallMemory` 优先走语义，失败退回关键词 |
| `lib/agent/pipeline.ts` | DONE 前统一建索引，失败不影响会议成功 |

## 踩坑记录

**第一版用了绝对阈值 0.2，结果把正确结果也筛掉了。**
「上线时间是什么时候」→「月底发布第一个版本」的相似度只有 0.154，被 0.2 阈值拦下。
后来加了相对阈值，但「今天天气」仍能过 0.178——这才发现单靠分数根本分不开，
必须结合关键词是否命中。

**索引失败不能让会议失败。**
建索引包在 try/catch 里，失败只发一条 `index_semantic` 失败事件，检索会自动退回关键词。

## 不做
