## 现象

在会中提问里问：

> 对方说了什么？
> 我说了什么？
> 李娜说了什么？

系统回答「没有找到相关内容」，而转写里明明有大量发言。

## 根因：把「谁」当成了要检索的内容

转写里说话人是**角色标签**：

```
speaker_0 = 我（本机麦克风）
speaker_1 = 对方（系统播放音）
```

而「谁说的」其实是**过滤条件**，不是检索内容。旧逻辑没有区分这两件事：

| 问法 | 旧逻辑切出的检索词 | 结果 |
|---|---|---|
| 对方说了什么 | `["方"]` | 拿单字「方」去原文里找，必然零命中 |
| 我说了什么 | `[]` | 恰好走了"无实体词 → 返回最近几条"，歪打正着 |
| 李娜说了什么 | `["李娜"]` | 拿人名去搜原文，可原文里只有「我/对方」 |
| 张伟说了什么 | `["张伟"]` | 同上 |

「我说了什么」看起来能用，纯属巧合：它恰好没有任何可检索词，被当成「刚才说了什么」处理了。

## 修法

### 1. 分离「说话人」与「话题」

新增 `parseSpeakerQuery()`：

- 人名匹配优先（从会议参与者表读真实姓名，长的优先，避免「李」抢走「李娜」）
- 再匹配角色词（对方 / 对面 / 别人 / 我 / 本人…）
- **必须同时出现"说/讲/提到/聊/谈"这类动词**，否则「对方的需求是什么」是在问话题，不能误判
- 第一人称要求紧邻说话动词，避免「我觉得这个需求有问题」被当成「我说了什么」

拿到说话人后，用 `stripSpeakerWords()` 剥掉"谁+说话"这层壳，剩下的才是话题：

```
对方说了什么        → 说话人=对方, 话题=""
对方说联调怎么安排   → 说话人=对方, 话题="联调怎么安排"
我说风险           → 说话人=我,   话题="风险"
```

### 2. 检索与上下文都按说话人过滤

`rankSegments()` / `buildContext()` 新增 `speaker` 选项：

- **检索**只在该说话人的片段里进行
- **上下文**也只放这个人的发言，并在标题里写明「只含「对方」的发言」
- 说话人问法下零命中**不再短路**成"没找到"，而是让模型看着他的原话回答

上下文过滤这点特别重要：如果只过滤检索、不过滤上下文，模型会把别人的话也当成"对方说的"——
**给出错误归属比答不出来更糟**。

### 3. 三档匹配强度

说话人场景下材料很少（通常就几句），但也不能放宽到乱召回：

| 情况 | 规则 |
|---|---|
| 有实体词（「对方说联调」） | 必须真的出现「联调」，意图词（安排/负责）不算 |
| 只有意图词（「对方提到了风险」） | 字面出现即可，但**仍限在这个人范围内** |
| 没有话题（「对方说了什么」） | 返回他的全部发言，按时间顺序 |

## 踩坑记录

| 坑 | 现象 | 修法 |
|---|---|---|
| 剥离后空串被兜回原句 | `topic = strip() \|\| question`，空串又变回「对方说了什么」，继续零命中 | 空串是合法结果，直接传下去 |
| 角色词被当人名跳过 | 名字表里的「对方」「我」两个键在剥离时被 `length >= 2` 的判断带过 | 角色词改用正则统一剥，不依赖遍历顺序 |
| 残留单字碎片 | 剥完留下「说」「的」，单字在转写里几乎必然出现，造成误召回 | 所有单字虚词一律清掉 |
| 意图词当实体词 | 「对方说联调怎么安排」里「安排」是意图同义词，召回了"测试用例我来跟进" | 说话人+有实体词时，只认实体词 |

## 验证

真实模型端到端：

**「对方说了什么？」**
> 对方在会上说了三件事：后端接口大概周三给到，前端等接口才能联调（00:06）；
> 让张伟负责搭联调环境，最晚周四给大家（00:23）；测试用例由对方跟进，下周一前补齐（00:42）。

出处 3 条，全部是 `speaker_1`。

**「我说了什么？」**
> 你主要说了三点：开场定下今天对齐季度上线排期（00:00 我）；定下前端先做静态页面、
> 接口周三到位后立刻联调（00:14 我）；并提示风险——周三接口给不出来，联调会延期一周（00:32 我）。

**「对方提到的风险是什么？」**（对方确实没提风险）
> 对方在会上没有明确提过「风险」这个词。他只说了时间安排：后端接口周三给、
> 联调环境最晚周四（00:23）、测试用例下周一前补齐（00:42）。

最后这个是关键：不再是笼统的"没有找到相关内容"，而是**基于对方的原话说清楚他到底讲了什么**。

## 回归测试

`pnpm test:live-qa` 新增 A9 组 18 项，覆盖说话人识别、过滤正确性、
上下文只含该说话人、无发言时的针对性提示，以及
**「我觉得这个需求有问题」「对方的需求是什么」不能被误判为说话人问法**。
