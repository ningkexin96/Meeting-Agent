## 现象

在 test01 这场会（42 条转写）里问：

> 总结一下会议

系统回答：

> 本次会议的转写和往期记忆里都没有找到和「总结一下会议」相关的内容。可以换个说法再问一次。

而屏幕上明明就摆着 42 条转写。这是会中问答最不该出现的失败——
用户要的是"概括你已经看到的内容"，系统却在**找"总结"这两个字**。

## 根因（两层叠加）

**第一层：把元词当成了实体词。**

`tokenizeQuery("总结一下会议")` 切出来是 `["总结", "议"]`，
这两个词既不在停用词表里，也不在意图词表里，于是被当成**具体实体词**，
要求它们在转写原文里出现。可开会时没人会说"总结"二字，所以必然零命中。

**第二层：零命中被当成"查不到"的判据。**

`prepareQuestion()` 里有一条守卫：

```ts
if (hits.length === 0 && memories.length === 0) {
  // 直接返回"没有相关内容"，不调模型
}
```

命不中任何词，就直接判定"没有内容"。对找话题的问题这是对的（防止编造），
对"概括整场会议"这类问题则是错的——**它压根不该去原文里找词**。

## 修法

### 1. 识别"元问法"

新增 `isMetaSummaryQuery()`，用一组模式覆盖真实问法：

| 问法 | 是否概括 |
|---|---|
| 总结一下会议 / 概括一下 / 归纳 / 梳理 / 复盘 | ✅ |
| 会上讲了什么 / 这场会主要说了啥 | ✅ |
| 帮我概括一下 | ✅ |
| **刚才说了什么** | ❌ 这是要"最近几句"，不是全场概括 |
| 现在说到哪了 | ❌ 时间窗 |
| 谁负责联调 | ❌ 具体话题 |

关键的一条排除规则：`刚才|刚刚|最近|现在说到` 优先判为时间窗。
两个意图都命中「说了什么」的句式，不区分的话，问"刚才"会拿到全场的均匀抽样。

### 2. 元词表与实体词分离

`SUMMARY_WORDS`（总结/概括/归纳/结论/要点/内容/会议/这次…）不参与检索匹配。
这样 `coreTerms` 为空，检索走"没有具体话题"的分支。

### 3. 概括类走专用路径

- **检索**：按时间**均匀抽样**（`sampleTermsForSummary`），保证包含首尾。
  不能取"最相关的 6 句"——概括出来的"会议总结"会完全跑偏，
  因为最相关的几句往往是同一个话题反复出现的地方。
- **上下文**：带 `summarize: true` 时纳入整场转写（受字符预算裁剪），
  并注明"共 N 段，为控制长度只提供最近 M 段"，让模型知道自己看到的是全部还是部分。
- **提示词**：注入 `SUMMARY_RULES`，明确三件事：
  1. 用 3~5 句话概括（主题 → 讨论/结论 → 待定或风险）
  2. 内容零散时如实说"主要是试音/寒暄，没有实质议题"，**不要硬凑结论**
  3. **不要因为转写里没有"总结"二字就说找不到**，材料就是要概括的对象本身

### 4. 守卫加例外

```ts
if (!summarize && hits.length === 0 && memories.length === 0) {
  // 零命中兜底
}
```

### 5. 带话题的概括仍然聚焦

「总结一下联调这块」里「联调」是真实话题，此时仍按话题检索，
只是额外带上概括指令。两件事不冲突。

## 验证

用 test01 的真实数据（42 条试音录音）端到端验证：

**修复前**：`本次会议的转写和往期记忆里都没有找到和「总结一下会议」相关的内容`

**修复后**：

> 这场会主要是试音和确认手机外放能否传声，没有实质议题。双方反复确认能否听见、
> 让对方外放视频，期间我这边一直听不到（01:38 我），最后我说「没事了」（02:51 我）。
> 没有形成任何结论，也没有待办事项。

另一场 test01（2 条转写，有真实议题）也能正确概括出决议、责任人与风险。

## 回归测试

`pnpm test:live-qa` 新增 A8 组 16 项，覆盖：

- 5 种概括问法都被识别
- 「刚才说了什么」「现在说到哪了」「谁负责联调」**不**被误判为概括
- 概括类不会零命中
- 纯概括问法没有可检索实体词
- 抽样包含开头与结尾
- 提示词含概括指令、非概括问法不含
- 「总结一下联调环境」按话题聚焦
